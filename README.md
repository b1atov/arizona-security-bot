# arizona-security-bot

Копия оригинального Arizona Security Bot
Telegram-бот для привязки игрового аккаунта к Telegram: пользователю выдается 6-значный код, который необходимо вести в игре. 

Привязка со стороны игры (проверка кода и получение ID) в этом репозитории **не реализована** — бот только выдаёт код и кэширует в Redis.

## Возможности

- `/start` и кнопка «Начать» — приветствие
- «Получить код» — код привязки (нужна подписка на канал)
- «Проверить подписку» — повторная проверка на подписку 
- «Узнать ID профиля» — Telegram user id (для восстановления аккаунта в игре)
- «Дополнительные рассылки» — статус подписки на доп. рассылки. 

## Требования

| Компонент | Версия / условие |
|-----------|------------------|
| Python | **3.12+** (в коде используются вложенные кавычки в f-string) |
| Redis | любой совместимый с клиентом `redis` ≥ 5 |
| Зависимости | см. [`requirements.txt`](requirements.txt): `aiogram==2.4.0`, `redis>=5.0.0`, `python-dotenv==1.0.1` |

Бот должен быть **администратором канала**. Иначе `get_chat_member` падает, а проверка подписки всегда возвращает «не подписан».

## Быстрый старт

1. Клонируйте репозиторий и перейдите в каталог проекта.

2. Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
```

3. Запустите Redis (локально или удалённо) и убедитесь, что к нему есть доступ.

4. Скопируйте пример окружения и заполните значения:

```bash
cp .env.example .env
```

5. Запустите бота:

```bash
python main.py
```

Бот работает в режиме long polling.

## Конфигурация

Переменные задаются в `.env` (файл в `.gitignore`, в git не коммитьте).

| Переменная | Обязательна | Описание |
|------------|-------------|----------|
| `bot_token` | да | Токен бота от [@BotFather](https://t.me/BotFather) |
| `channel_username` | да | Username канала **без** `@` (для ссылок и текста) |
| `channel_id` | да | Числовой id канала (для `get_chat_member`), например `-100…` |
| `redis_host` | нет | Хост Redis, по умолчанию `localhost` |
| `redis_port` | нет | Порт Redis, по умолчанию `6379` |
| `redis_password` | да | Пароль Redis (обязателен) |

Шаблон: [`.env.example`](.env.example).

## Как это работает

```text
Пользователь → бот → проверка подписки (Telegram API)
                   → генерация кода + Redis →  Проверка на стороне игры (вне этого репо)
```

1. Пользователь открывает бота и подписывается на канал.
2. Нажимает «Получить код» — бот выдает код и кэширует в Redis
3. В игре: `/mn` → Личные настройки → Защита VK / Telegram → Привязка Telegram → ввод кода.
4. Игровой мод читает `active_code:{code}` и связывает аккаунт с Telegram user id.


### Ключи Redis

| Ключ | Значение | TTL |
|------|----------|-----|
| `code_cooldown:{userId}` | выданный код | 600 с (10 мин) |
| `active_code:{code}` | Telegram user id | 600 с (10 мин) |

Пока живёт `code_cooldown`, повторная генерация для того же пользователя блокируется (в ответе — оставшееся время в минутах).

## Структура проекта

```text
arizona-security-bot/
├── main.py                 # Bot, Dispatcher, polling
├── handlers/
│   ├── message_handlers.py # /start, reply-кнопки
│   └── callback_handlers.py# get_code, sub_check
├── keyboards/              # Reply и inline-клавиатуры
├── database/
│   └── redis.py            # клиент Redis, generate_code
├── utils/
│   └── check_subscribe.py  # проверка членства в канале
├── requirements.txt
└── .env.example
```

Точка входа: `python main.py` → импорт хендлеров → `executor.start_polling`.

## Безопасность

- Не коммитьте `.env` и не публикуйте `bot_token`.
- Коды живут в Redis с TTL 10 минут; 
- Проверка кода и привязка аккаунта — зона ответственности игрового сервиса;
